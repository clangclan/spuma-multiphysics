# 1스텝 시간 단축: 정밀도 완화 외 최적화 (2026-09-25)

기준은 main 46d8598(`closureSearch stableGasPrune`, 3.46 s/스텝)이다. 벤치마크는 모두 40 bar 160³ 사례의 200 μs 체크포인트에서 10스텝을 진행하고, 2–10스텝 평균을 냈다. 같은 조건의 기준 결과와 `reactiveState.bin`을 비트 단위로 비교했다.

## 결과

| 단계 | 스텝 [s] | HEM 커널 [s] | 백업 [s] | 최종 상태 |
|---|---:|---:|---:|---|
| main, `stableGasPrune` | 3.460 | 1.269 | 0.288 | 기준 |
| + 백업 버퍼 재사용·병렬, HEM 호스트 루프 병렬 | 3.130 | 1.269 | 0.053 | 비트 동일 |
| + 멈춘 전 기체 Newton 조기 종료 | **2.325** | **0.460** | 0.053 | **비트 동일** |
| (참고) main, `reference` | 7.78 | 5.59 | 0.29 | 기준 |
| (참고) 이번 빌드, `reference` | 7.46 | — | — | 비트 동일 |

`stableGasPrune`에서 스텝 시간은 **3.46 s → 2.33 s(−33%)**, 처음(7.78 s) 대비 **3.3배** 빨라졌다. 10스텝 뒤 상태는 `reference` 모드 결과와도 비트 단위로 같았다. CPU fallback과 장치 실패는 모두 0이었다.

## 1. 백업 버퍼 재사용·병렬화 (`src/reactiveFoam/ReactiveFoam.C`)

- **이전:** 스텝마다 `const Array previous=q; const SavedStates previousStates(states,mechanical);`로 약 1 GB를 새로 할당해 단일 스레드로 복사했다.
- **변경:** 두 버퍼를 스텝 반복 밖에 두어 재사용한다. 복사는 `reactiveParallel::forEach`로 한다. `SavedStates::save/restore`도 병렬화해 RK2 seed 복원에도 적용했다.
- **효과:** 0.288 → 0.053 s/스텝. 결과는 바뀌지 않는다.

## 2. HEM 호스트 루프 병렬화 (`src/reactiveTransport/reactiveGpuHem.cuh`)

- 모세관 입력 검사, bucket 정렬(무거운 셀 먼저), 결과·성공 플래그 반영을 병렬화했다.
- bucket 정렬은 chunk별 개수 → bucket 안에서 chunk 순서대로 offset → chunk별 배치의 안정 계수 정렬이라, 직렬과 같은 순열을 만든다.
- **효과:** HEM wall 약 −0.08 s/스텝.

## 3. 멈춘 전 기체 Newton 조기 종료 (`src/reactiveThermo/reactiveDeviceFlash.h`)

**원인 추적.** 탐색 생략 이후 남은 HEM 시간(1.27 s/스텝)은 소수의 액체 셀에서 나왔다([정밀도 완화 시험](hem-precision-relax-20260925.ko.md)). 진단 빌드로 탐색 단계별 cycle을 재 보니, 두 상 seed가 아니라 **첫 후보인 전 기체 `frozen()`**이 거의 전부였다.

| 단계 (200 μs 액체 1,332셀) | 호출 | 상 평가 | 호출당 cycle |
|---|---:|---:|---:|
| 전 기체 frozen | 1,332 | 330,028 | 2.1×10⁸ |
| 두 상 seed Newton | 6,660 | 75,392 | 3.9×10⁶ |
| seed 후보 안정성 검사 | 6,660 | 13,320 | 4.3×10⁵ |

가장 느린 셀(935번)에서 전 기체 (p, T) Newton을 추적했다. 부피 잔차가 −1.29×10⁻²에 머문 채 매 반복 약 2⁻¹⁰ 크기의 보폭만 받아들이며 70회를 기어갔고, 845회의 상 평가 뒤 실패했다. 액체 밀도의 N₂O를 모두 기체로 두는 상태를 찾으려다 수렴하지 못하는 것이다.

125/150/170/200 μs 체크포인트의 N₂O 셀 전체를 재생해 이 경로(scalar 기체 fast path를 쓰지 못한 셀)를 모두 셌다.

- 3,396회 중 성공은 4회뿐이었고, 모두 **3번째 반복 안에** 수렴했다.
- 실패는 모두 5회 이상 반복한 뒤였다. 3,232회는 line search 실패로, 160회는 70회 한도로 끝났다.

**변경.** `frozen()`에 `stallLimit`를 추가했다. 받아들인 line-search 비율이 1/32 미만인 반복이 4번 연속되면 실패로 끝낸다. 이 규칙은 `closureSearch stableGasPrune`이고, 후보가 전 기체이고, adaptive 탐색이 아닐 때만 켜진다. `reference` 모드와 다른 frozen 호출(전 액체, 비평형 모세관)은 바뀌지 않는다. 정책 태그를 `stable-gas-prune-v2`로 올렸다.

**검증.**

| 입력 | 셀 | 비트가 다른 셀 | HEM 커널 [ms] 전 → 후 |
|---|---:|---:|---|
| 125 μs N₂O 전체 | 766,280 | 0 | 228.8 → 39.1 |
| 150 μs | 918,900 | 0 | 200.1 → 45.6 |
| 170 μs | 980,538 | 0 | 266.2 → 44.7 |
| 200 μs | 1,027,686 | 0 | 152.1 → 44.2 |
| 200 μs 액체/곡면 셀 | 1,332 / 2,520 | 0 / 0 | 143 → 34 / 142 → 34 |
| 전체 솔버 10스텝 | 4,096,000 | 최종 상태 동일 | HEM 커널 1.269 → 0.460 s/스텝 |

**한계.** 규칙의 근거는 "멈춘 전 기체 Newton은 이 데이터에서 한 번도 수렴하지 않았다"는 실증이다. 수렴하지 않는다는 증명은 아니다. `stableGasPrune`과 같은 검증 범위(40 bar N₂O/공기, 125–200 μs 및 10스텝)에 묶이고, 다른 조건에서는 같은 재생 비교를 먼저 해야 한다.

## 시도했지만 적용하지 않은 것

- **무거운 셀 후보 병렬 커널.** 전체 탐색이 필요한 셀을 먼저 표시한 뒤, 32레인 블록에서 후보를 레인마다 나눠 계산하는 2단계 커널을 구현했다. 셀 1개/warp와 셀 4개/warp 두 방식 모두 결과는 **비트 동일**했다. 그러나 1,332 액체 셀이 143 → 245 ms(셀 1개/warp), 143 → 227 ms(셀 4개/warp)로 **느려졌다**. 한 셀만 보면 935번이 57.7 → 110.8 ms였다. 직렬 Flash의 "사용 불가 액체" 메모를 레인마다 다시 계산하는 탓(상 평가 1.8배)으로 보인다. 3번으로 원인을 찾은 뒤에는 필요도 없어져 되돌렸다. 기록은 `results/hem-precision-relax-20260925/negative/`에 있다.
- **블록 크기 32/128.** 차이가 없었다([정밀도 완화 시험](hem-precision-relax-20260925.ko.md)).
- **pinned 전송.** pageable H2D가 이미 22 GB/s(pinned 27 GB/s)라 이득이 작다고 판단했다.

| CFL과 RK 단계의 `packTransport`·계면 기하 중복 | 약 0.1–0.2 | WALE PR 속성은 epoch 토큰(`nextConserved`, `geometryVersion`)으로 엄격히 검사된다. 결과를 재사용하려면 수송 라이브러리의 토큰 규약을 바꿔야 한다. |

## 현재 모습 (2.33 s/스텝, Nsight 3스텝)

- **GPU:** busy 약 50%다. HEM 커널 0.45 s, 수송 커널 0.28 s, WALE 0.09 s, H2D/D2H 복사 0.44 s.
- **GPU 유휴의 주 원인:**
