# 최적화 리뷰 후속 실험 결과 — 2026-09-10

**리뷰의 세 코드 문제를 재현하고 수정했다. 120스텝 비교와 자동 수치 판정은 통과했다. 추가 alpha 초기화 제거의 독립적인 속도 이점은 확인되지 않아 기본 비활성으로 유지했다.**

검토 대상은 「최적화 상태 검토」와 기존 비공개 저장소 `bc900a5` 스냅숏(로컬 `713fc8c`)이다. MAIN이 모든 코드·도구를 작성하고 빌드·실행·판정했다. 보조 에이전트는 독립 검토를 수행했다. [실험 계획](review-experiment-plan.md), [재현 명령](../README.review-experiments.ko.md), [집계·해시 JSON](review-experiments.json)을 함께 보관한다.

## 수정과 직접 회귀시험

| 항목 | 기존 동작과 수정 | 실행 결과 |
|---|---|---|
| Euler 제한 | 기본 localEuler만 검사하던 경로에 실제 `ddt(alpha.<phase>)` 선택 검사를 추가했다. `limit`과 `explicitSolve` 진입 시 모두 검사한다. | Euler 통과. 기본 backward, IPA별 backward, IPA별 localEuler 모두 거부. |
| 접촉각 캐시 | 접촉각이 U에 의존하지만 alpha가 바뀔 때만 캐시를 비웠다. 접촉각 경계가 있으면 캐시를 우회하고 기존 캐시도 지운다. | 고정 alpha에서 U 변경으로 힘이 4,783.45만큼 달라졌다. 기존 캐시의 정규화 오차는 0.27524, 수정 경로는 (2.82\times10^{-16}). |
| 온도 허위 수렴 | 음수 nSweeps의 stock metadata가 잔차 0을 반환했다. 이제 실제 FP64 보정 잔차를 계산하고 유한성·수렴 확인 후 T에 적용한다. | 한 sweep의 실제 잔차는 default norm 0.25, norm none 0.5. 기존 코드는 성공 처리했고 수정 코드는 거부했다. 24 sweeps는 통과. |
| 상태 검사 | U의 내부 셀 유한성과 alpha 범위·합 진단을 추가했다. strict 모드에서 alpha·질량 기준을 넘으면 중단한다. | 모든 새 benchmark가 strict 모드로 통과했다. |
| limiter 저장소 | FP64·FP32 ratio 배열을 동시에 잡던 경로를 선택한 정밀도의 지연 할당으로 바꿨다. | 기본 GPU 모드에서 불필요한 FP32 payload 24.76 MB, mixed 모드에서 FP64 payload 49.51 MB를 줄인다. 실제 VRAM 감소량 측정은 아니다. |

직접 회귀시험 **13개가 모두 예상 결과를 냈다**. 여기에는 별도 보관한 기존 라이브러리로 두 오류를 재현하는 대조군이 포함된다. 온도 검사에는 tolerance=0.3에서 default norm만 통과하도록 하는 대조도 넣어 정규화 오류를 구분했다. 접촉각 일치 기준은 힘의 크기로 정규화한 (10^{-12})이며, 비캐시 재계산의 GPU 합산 순서 차이를 허용한다.

별도로 외부 Pintle restart 없이 만드는 **1,152셀·세 상·동적 접촉각 case**를 작성했다. 실제 격자 좌표로 초기장을 만들며 초기 셀 수 IPA 170, N2O 190, air 792를 확인한다. 이 case의 8스텝 A/B, stock limiter·limitSum·explicitSolve oracle, 마지막 순차 갱신 재현이 통과했다. 작은 case의 시간은 성능 근거로 사용하지 않는다.

## 자동 판정

실험 전에 기록한 [v1 정책](../policies/numerical-acceptance-v1.json)을 적용했다. 기존의 측정 전용 `benchmark.py`는 유지하고, 새 실행기·판정기가 실패 시 비정상 종료하도록 했다.

- p/T/rho 양성, 필수 출력과 내부 셀 U·alpha 유한성.
- alpha 범위 허용 (10^{-8}), 합 오차 (10^{-9}), 스텝별 상대 총질량 수지 오차 (10^{-6}).
- `max_scaled = max(abs(candidate-reference))/max(1,max(abs(reference)))`: p는 (10^{-5}), U/T/rho/alpha는 (10^{-6}).
- 실행·비교 쌍의 누락/중복, 시간 표본, mini oracle과 replay 결과 검사.
- 로그·실행 정의·최종 필드·replay 파일 SHA-256 검사.

**정상 대조 1개와 실패 대조 13개**를 실행했다. 비유한 U, 필드 누락, alpha 범위·합, 질량 오차, 상태 진단 누락, 필드 차이, 실행 누락·중복, 비교 중복, 보호 입력 변경, replay 누락, 실제 로그 변조가 모두 CLI 실패로 이어졌다. 이들은 측정 보고서의 격리된 사본을 변형한 판정기 시험이며 솔버에 물리 오류를 주입한 시험은 아니다. 해시 묶음은 실행 자료의 변경을 확인하는 용도이며 인증된 보관 형식을 의미하지 않는다.

Replay의 반올림·source·증가량 허용치는 `analyze_alpha_replay.py`에 따로 기록되어 있다. QoI는 별도의 합격 허용치를 적용하지 않는 기술 지표다. 상기 v1 JSON이 이 모든 기준을 하나로 정의한다고 해석하면 안 된다.

## 실제 Pintle 120스텝 검증

3,094,455셀에서 **45→48.6 μs**, dt=30 ns로 진행했다. 기존 12스텝 검증보다 시간 구간이 10배 길다. 기준은 기존 multicolor smoother, 후보는 async smoother와 alpha source 초기화 제거다. 두 설정 모두 같은 수정 바이너리, FP64, 물성, 선형 풀이 허용오차를 사용했다.

| 최종 필드 | 최대 절대 차이 | 체적 가중 상대 L2 |
|---|---:|---:|
| p | 0.04277 Pa | (7.82\times10^{-10}) |
| U | (6.22\times10^{-7}) m/s | (6.00\times10^{-11}) |
| T | (1.01\times10^{-7}) K | (7.39\times10^{-14}) |
| rho | (2.01\times10^{-6}) kg/m³ | (6.24\times10^{-12}) |
| alpha.ipa | (2.66\times10^{-9}) | (1.10\times10^{-12}) |
| alpha.n2o | (4.15\times10^{-8}) | (3.44\times10^{-10}) |
| alpha.air | (4.15\times10^{-8}) | (1.23\times10^{-11}) |

U의 최대 절대 차이는 성분 기준, 체적 가중 L2는 벡터 기준이다. 모든 스텝에서 비유한 내부 상태와 alpha 범위 위반은 0이었다. 최대 상분율 합 오차는 (5.95\times10^{-13}), 상대 총질량 수지 오차는 (5.06\times10^{-8}) 이하였다. 두 실행의 **1,920개 선형 풀이 순서와 총 3,769회 반복 횟수가 정확히 일치**했다.

최종 raw dgdt의 정규화 차이는 IPA 0.657, air 0.290으로 여전히 크다. 이를 동등성 지표로 사용하지 않고, **실제로 alpha 풀이가 소비한 dgdt와 divU를 별도 저장**했다. 마지막 `solveAlphas` 호출은 번호 479, subcycle dt=15 ns였다.

- IPA→N2O→air 순서로 앞 상의 갱신값을 반영해 Sp/Su를 재계산했다. 모든 source 분기가 실행됐고, FP64 반올림 허용 경계를 넘은 셀은 0이었다.
- 저장한 old alpha와 stock flux divergence로 explicit update를 재계산한 최대 정규화 차이는 (3.34\times10^{-16}) 이하였다.
- 두 설정 사이의 `dt*(Sp*alpha_before+Su)` 최대 차이는 (3.32\times10^{-11}), 실제 상별 alpha 증가량 차이는 (1.27\times10^{-8}) 이하였다.

이 replay는 **마지막 호출의 phase-sum 보정 전 상태**를 검증한다. 모든 과거 호출의 source를 직접 저장·검증한 것은 아니다. 계수 oracle의 합산 순서는 현재 custom kernel의 상 목록 순서를 따른다. upstream의 self-first 부동소수점 합산 순서와 비트 단위로 같다고 주장하지 않는다.

상별 후처리에서는 체적, 상 질량, 무게중심, 계면 gradient 지표와 mixed volume을 비교했다. 재구성한 상 질량의 최대 상대 차이는 (1.46\times10^{-13}), 무게중심 거리 차이는 (6.90\times10^{-15}) m, gradient 지표의 상대 차이는 (2.51\times10^{-11}) 이하였다.

상 밀도·내부에너지는 저장된 p/T와 사용한 물성 모델로 **재구성한 값**이다. 종료 직후 압력으로 선형 보정한 내부 밀도와는 다를 수 있다. 실제로 재구성한 상 질량 합은 저장된 총질량보다 약 (3.13\times10^{-9}) kg 컸다. 같은 모델의 에너지 기준을 유지한 sensible internal + kinetic inventory 차이는 약 (2.07\times10^{-7}) J였다. 경계 열·압력일·유입출을 적분한 에너지 보존수지 검사는 수행하지 않았다.

이 구간에서 기준 실행의 N2O 무게중심 z는 약 0.102 mm 이동했고, N2O gradient 지표는 8.19%, mixed volume은 15.91% 증가했다. 따라서 정지된 초기장을 반복 비교한 시험은 아니지만, 장기 물리 검증으로 확대할 수는 없다.

## 추가 초기화 제거의 성능

성능 실험에서는 **두 설정 모두 async smoother**를 사용하고 `pintleFuseAlphaSource`만 켜고 껐다. 12스텝씩 균형 순서로 네 쌍을 비교했다. 첫 두 스텝과 마지막 출력 스텝을 제외한 9개 시간의 평균을 실행별 값으로 사용했다.

| 유효 쌍 | 전체 시간 감소 | 변경하지 않은 단계 합의 감소 | alpha/다른 단계 시간 비율 감소 |
|---|---:|---:|---:|
| 1, 재측정 | 1.864% | 1.612% | 0.659% |
| 2 | 7.294% | 7.421% | −0.531% |
| 3 | 6.126% | 6.401% | −0.723% |
| 4 | 9.507% | 8.982% | 1.102% |

원래 첫 쌍은 후보 실행 중 CPU 배열 분석과 겹쳐 제외하고 한 쌍 전체를 다시 측정했다. 겹친 시각과 제외·대체 자료는 JSON에 남겼다. 출력·원자료는 삭제하지 않았다.

원시 시간 감소의 중앙값은 6.710%지만, **변경하지 않은 에너지·운동량·압력·난류 단계도 6.911% 감소**했다. alpha의 상대 비율은 개선 두 쌍·악화 두 쌍이었다. 장치의 데스크톱 메모리 사용량도 실행 중 변했다. 따라서 원시 6.710%를 초기화 제거의 속도 향상으로 인정하지 않았다. 별도 120스텝 한 쌍에서는 후보가 4.309% 느렸으며, 이 단일 순서 측정도 성능 결론으로 일반화하지 않는다.

**`pintleFuseAlphaSource`는 기본 false를 유지한다.** 옵션의 수치 검증과 중복 초기화 제거 자체는 완료했지만, 독립적인 속도 이점은 추가 통제가 필요하다. 앞선 12.68배나 async 3.8% 결과를 이번 변경의 효과에 더하지 않았다.

## 남은 범위

120스텝도 실제 시간으로는 3.6 μs다. 장기 물리 타당성, Foundation 14와의 수치 동등성, 모든 경계조건·MPI·가변 격자, 완전한 에너지 수지는 검증하지 않았다. 기존 sanitizer 보고의 범위도 확대해 해석하지 않는다. CUDA Graph, 실제 SM/DRAM 하드웨어 카운터, 모든 중간 source 호출과 장기 계면·열수지 검증은 별도 후속 작업이다.

원본 생산 입력은 실행·수정하지 않았다. 모든 실행은 복사본에서 수행했고 보호 입력·실행 바이너리·유효 소스의 해시를 확인했다. 이번 결과는 기존 보고서를 대체하는 물리 인증이 아니라, 리뷰에서 제기된 코드 제한과 회귀 검증을 구체화한 추가 증거다.
