# ReactiveFoam 탐색 최적화·CUDA 후보 확장 검증 — 2026-09-21

기준 커밋은 `cbce10fb6f3e8554449e9aafc6a4442b2ced633d`이다. 기존 R04 실행의 99.36%를 차지했던 상태 복원에 정확 입력 재사용과 순수 액상 물성 재사용을 추가했다. CUDA에는 응축성 inventory가 없는 기상의 PR/NASA 온도 후보 복원을 연결했다. 전체 다상 flash는 여전히 CPU에서 수행한다.

## 변경

- 비반응 HEM 평형에서 `thermoExactReuse`를 기본 활성화한다. q/E/초기 상태 전체를 FP64 비트 수준으로 비교하고 원본 비교로 해시 충돌을 배제한다. 배치 경계를 넘어 상태 결과를 재사용하지 않는다.
- 한 복원 내부에서 순수 액상의 같은 p/T 물성을 액상별 16개 슬롯에 보관한다. 성공한 물성만 저장하고 공개 Cantera 객체 상태도 복원한다. 화학퍼텐셜 출력 버퍼는 작업자별로 재사용한다.
- `closureScalarBackend cuda`는 FP64 NASA7/9+PR e/cv/p 및 온도 Newton/구간 축소를 GPU에서 수행한다. 기존 호스트 EOS 분지·잔차·안정성·엔트로피 검사로 승인한다. 단상 후보만으로 전체 HEM 승인을 대체하지 않는다.
- 추가 메모리와 수치 정책 식별, 실제 GPU 라이브러리 해시, CPU 분류/준비 및 GPU 커널/전송 타이머를 연결했다. 기존 C ABI 구조체는 변경하지 않았다.

| 검증 묶음 | 통과 항목 |
|---|---:|
| 기존 정상·포착 실패·trace inventory·음속·worker 회귀 | 388 |

| ABI·메모리·정책 변경·CUDA 오류·잘못된 GPU 후보·실패 원본 ID | 9 |

| CPU/CUDA 물리 선택 회귀 | 36 |
| 합계 | **461** |
| 별도 R04 저장 상태 4,096셀 OFF/ON 비교 | **2** |

새 가속 시험의 정상 3개와 포착 입력 256개를 복제해 각 worker 수에서 비교했다. 물리 상태 비교의 최대 scaled 차이는 0이었다. GPU 고유 기상 입력 512개 시험은 최대 차이 7.9722e-9 이내였다. 일반화된 비교 허용치는 1e-8로 고정했고, 상태 승인에는 기존 잔차 허용치를 그대로 사용했다. 반복 횟수와 잔차 필드 자체는 물리 상태 오차 비교에서 제외하며 솔버/백엔드의 기존 잔차 승인과 별도로 검사한다.

유동은 uniform air, 비확산 온도 변동, N2O 2상 acoustic의 16셀 케이스다. OFF/ON 최종 q 및 경계 적분 비교는 0, 재시작의 최대 q scaled 차이는 1.77e-14 미만이었다. 중간 배치 실패를 주입해 전체 단계 rollback, 재시도 1회 및 전역 보존을 확인했다. 이것은 대형 R04 유동의 재실행이나 새 물리 인증이 아니다.

## 측정한 성능

각 배치 입력을 동일하게 유지하고 3회 측정한 중앙값이다. OFF와 ON은 동일한 구현에서 옵션만 달리했다. 모델/GPU 초기화는 배치 타이머 밖이며 작은 테스트의 결과를 전체 메시 가속률로 외삽하지 않는다.

| 입력 | 기준 OFF | 정확 재사용 | 재사용 + CUDA 후보 |
|---|---:|---:|---:|
| 반복 상 상태 768셀 | 0.490047 s | 0.064711 s (**7.57배**) | 0.064095 s (**7.65배**) |
| R04 12 ns 체크포인트에서 균등 인덱스로 뽑은 4,096셀 | 8.361146 s | 6.739641 s (**1.24배**) | 6.723529 s (**1.24배**) |

R04 표본에서 동일 입력 재사용 비율은 20.70%였다. 3회 동안 순수 액상 물성 cache hit는 1,739,652회, miss는 2,342,169회였다. CPU 재사용만으로 배치 시간이 약 19.39% 줄었다. CUDA가 처리할 수 있는 고유 입력은 반복당 1개뿐이어서 추가 가속은 측정 잡음 수준이었다. 실제 저장 q/E와 복원 초기 상태를 사용했지만 다음 RK 단계의 새 q를 생성한 유동 시험은 아니다.

서로 다른 기상 상태 512개에서는 CPU 0.000526 s, 재사용+CUDA 0.000693 s였다. GPU 경로가 약 1.32배 오래 걸렸으므로 기본 활성화하지 않았다. GPU 커널 3회, 후보 1,536개 제출·호스트 승인, 거부 0회를 기록했다. 데이터 준비·전송·승인 비용을 포함한 결과이며 커널 시간만으로 가속을 주장하지 않는다.

## 남은 범위

R04에서 비용이 큰 응축성 성분/기액 공존 상태의 전체 후보 탐색·안정성·음속 계산은 CPU에 남아 있다. GPU 기능은 `deviceCaloricCandidates=true`로 보고하며 `deviceFullClosure=false`, `deviceChemistryIntegration=false`를 유지한다. GPU 이식 범위가 제한적이라는 사실을 전체 GPU 상평형 완료로 표시하지 않는다.

최악 셀의 음향 CFL과 30–50 ns 목표 간격 문제는 별도다. 메시, CFL, 원래 R04 입력과 대형 계산 상태를 변경하거나 다시 실행하지 않았다.

실행 환경은 RTX 5080 / sm_120, NVHPC 26.5 CUDA 13.2, Cantera 3.2.0, FP64이며 OMP/BLAS 내부 스레드는 1로 제한했다. GPU 실제 사용 근거는 커널·승인 카운터와 CUDA event 시간이다.
