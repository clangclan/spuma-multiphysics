## 원인과 수정

기존 R04 첫 실패 입력 24개와 과거 시험 수정본의 두 번째 스텝 실패 24개를 다시 확보했다. 두 번째 묶음은 기준 복원기가 통과했으며, 액체 분율 차분 폭의 일괄 변경이 회귀를 만든 것으로 확인했다. 기준 탐색을 보존한 첫 개선본은 이 48개를 통과했지만 전체 메시의 다음 입력에서 다시 실패했다.

새 진단으로 RK1 전역 셀 24377(0부터 시작), batch offset 20480/local 3897의 입력을 확보했다. 공기 재고가 액체보다 매우 작은데 이전 액체 질량은 새 종 재고를 초과했다. 고정 `1-1e-8` 분율 seed에서는 인위적으로 큰 IPA 기상량이 만들어져 시작 EOS 기상 branch가 사라졌다. 단순히 dt를 13회 줄여도 같은 탐색 문제가 지속됐다.

`boundaryFallback`은 같은 q/E에서 기상 재고의 로그 좌표, `expm1` 액체량과 직접 계산한 기상 재고를 사용한다. 입력 q/E나 미량 비응축성 재고를 자르지 않는다. 각 물리 후보의 안정성·화학퍼텐셜·음속 검사는 유지하며 경계에서는 기준/보조 탐색의 안정한 해를 엔트로피로 비교한다. 직렬과 pool의 원래 셀 순서, 실패 출력의 원자성도 유지했다.

모든 실패 셀의 요약을 기록하고 batch당 최대 16개의 원래 보존량/seed와 후보 trace를 JSONL로 남긴다. 준비된 [256개 입력](../tests/fixtures/r04-recovery.jsonl)은 전체 메시 없이 재생할 수 있다. 이전 tracer 48개와 새 상세 기록 208개를 보존했으며 중복 셀 입력도 임의 삭제하지 않았다.

## 승인 상태와 체크포인트

전역 보존 검사 전에 GPU attempt를 확정하던 순서를 변경했다. q·열역학 상태·시각·누적 경계 유량은 전역 검사까지 통과해야 승인한다. 반복 실패 시 직전 승인 상태를 저장한다. 실패 상세 파일의 I/O 오류는 수치 timestep 재시도로 처리하지 않는다.

최종 검토에서 GPU 실패 시 Flow 내부와 호출자 양쪽에서 취소하던 경로를 하나의 호출자 소유로 통합했다. 단일 실패는 정확히 한 번, 영구 실패 시험은 13번의 각 시도마다 한 번씩 성공적으로 취소되는지 검사했다. 수정 빌드에서 checkpoint/rollback 18개와 413종 화학 rollback/restart 6개를 다시 통과했다.

새 schema 3은 정확한 이진 q, 열역학 seed, 최초 전역 보존 기준, 누적 경계 유량, 정확한 시각/직전 dt와 누적 스텝·재시도 수를 저장한다. 모든 파일과 complete marker를 숨김 디렉터리에 작성한 뒤 fsync/원자적 rename으로 노출한다. 기존 checkpoint를 교체하는 도중 실패해도 이전 완료 파일은 유지한다. 표식 누락·checksum 불일치·구조 불일치는 거부한다. 기존 schema 1/2 입력 읽기는 유지한다.

재시작 비교는 연속 40스텝과 20+20스텝을 비교했다. 열린 경계 감압에서도 누적 유량을 유지했으며 momentum 경계 적분은 약 `1.6e-4`로 0이 아닌 이력을 검사했다. 그 CPU/CUDA 경계 누적값 차이는 0이고 q 최대 정규화 차이는 `6.80e-15` 이하이다. 작은 주기 경계 재시작의 q 최대 차이는 `1.69e-14` 이하다.

동일 모델 참조와 수치 회귀 결과이며 실험 물성이나 분무 정확도 검증이 아니다. 293.15 K/4 MPa에서 N₂O와 IPA를 모두 액체로 초기화한 고밀도 혼합 상태의 일부 복원 실패는 남아 있다. 새 복원 모드는 비반응 HEM·종 확산 없음에 한정하고 나머지는 명시적으로 거부한다. GPU closure·device chemistry·표면장력·액적 분열·LES·MPI 지원을 추가한 것으로 표시하지 않는다.

## 전체 메시 인수

초기 개선본은 원본과 같은 조건에서 2스텝을 재시도 없이 진행해 이전 두 번째 스텝 실패를 넘었다. 후속 실행은 5스텝을 재시도 없이 통과했다. GPU 실패 취소 수정본의 인수를 위해 완료 체크포인트를 보존하고 런처를 명시적으로 중단했다. 최종 solver/backend를 고정한 새 프로세스에서 그 체크포인트를 읽어 G3를 진행한다. 이전 프로세스의 성공 스텝을 새 프로세스의 20스텝 인수에 합산하지 않는다.

G3는 최종 실행의 최소 20개 연속 승인 스텝, dt 유지, 기존 전역 수지 기준, 완료 체크포인트와 메모리 예산을 확인한 뒤 갱신한다. 이 조건 이전에는 P2 캐시/성능 최적화나 머지 완료를 주장하지 않는다.
